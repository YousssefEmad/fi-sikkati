# API Design

REST over HTTPS, versioned under `/api/v1`. OpenAPI 3.1 is generated by FastAPI and is the
contract: the TypeScript types/client in `packages/types` are generated from it (ADR-0009).
Nothing in this document is implemented yet; it defines the contract Phases 1–10 must follow.

## 1. Conventions

| Topic | Convention |
| --- | --- |
| Base path | `/api/v1` — breaking changes ⇒ `/api/v2`, old version kept ≥ 1 release |
| Resources | plural nouns, kebab-case: `/join-requests`, `/trips/{tripId}/join-requests` |
| Identifiers | UUID v7 strings |
| Bodies | JSON, `camelCase` fields (Pydantic alias generator) |
| Times | ISO-8601 with offset, always UTC on the wire (`2026-10-01T05:00:00Z`) |
| Money | `{ "amountMinor": 1900, "currency": "EGP" }` — never floats |
| Coordinates | `{ "lat": 30.2, "lng": 31.5 }` (WGS-84); geometry as GeoJSON `LineString` |
| Actions | sub-resources with verbs only for state transitions: `POST /trips/{id}/publish`, `/cancel`, `/start`, `/complete`, `POST /join-requests/{id}/accept`, `/reject`, `/cancel` |
| Auth | web: httpOnly cookies + `X-CSRF-Token`; mobile/API: `Authorization: Bearer <access>` (ADR-0004) |
| Idempotency | `Idempotency-Key: <uuid>` header required on `POST /trips/{id}/join-requests`, `POST /trips`, `POST /reports`; optional elsewhere. Same key + same user + same payload ⇒ same response; different payload ⇒ `409 IDEMPOTENCY_CONFLICT` |
| Locale | `Accept-Language` selects message language for `message` fields; the client should still map `code` → its own translation |
| Correlation | every response carries `X-Request-Id`; clients may send one |
| Rate limits | `429` with `Retry-After`; limits listed in `security.md` §7 |
| Caching | authenticated responses `Cache-Control: private, no-store`; public content pages cacheable |

## 2. Response envelopes

Single resource: the object itself. Lists: paginated envelope (ADR-0010).

```json
{
  "items": [ ... ],
  "pageInfo": { "nextCursor": "MDE5MmZ...", "hasMore": true, "pageSize": 20 }
}
```

- **Cursor pagination** (default) for user-facing feeds: trips, requests, messages,
  notifications, search results. Cursor is an opaque base64 of `(sort key, id)`. Params:
  `cursor`, `pageSize` (1–50, default 20).
- **Page pagination** for admin tables that need "page 7 of 40": params `page`, `pageSize`
  (≤100); envelope adds `totalCount`, `page`, `totalPages`.
- No endpoint returns an unbounded list (MEP §90).
- Filtering: explicit query parameters per endpoint (documented in OpenAPI), never a generic
  filter language. Sorting: `sort=departureAt` / `sort=-createdAt` from an allow-list.

## 3. Error format

RFC 9457 Problem Details plus a machine-readable `code` (ADR-0010). `Content-Type:
application/problem+json`.

```json
{
  "type": "https://fisikkati.app/errors/seat-unavailable",
  "title": "Not enough seats",
  "status": 409,
  "code": "SEAT_UNAVAILABLE",
  "detail": "Only 1 seat is available on this trip.",
  "requestId": "01J9…",
  "errors": [ { "field": "seatsRequested", "code": "MAX_EXCEEDED", "message": "…" } ]
}
```

| HTTP | Codes (non-exhaustive, registry lives in `core/errors.py`) |
| --- | --- |
| 400 | `VALIDATION_ERROR` (with `errors[]`), `INVALID_CURSOR`, `INVALID_TRANSITION` |
| 401 | `UNAUTHENTICATED`, `TOKEN_EXPIRED`, `SESSION_REVOKED` |
| 403 | `FORBIDDEN`, `ACCOUNT_INACTIVE`, `CSRF_FAILED`, `FEATURE_DISABLED` |
| 404 | `NOT_FOUND` |
| 409 | `SEAT_UNAVAILABLE`, `TRIP_NOT_ACCEPTING`, `REQUEST_NOT_PENDING`, `DUPLICATE_REQUEST`, `IDEMPOTENCY_CONFLICT`, `TRIP_OVERLAP`, `ALREADY_RATED`, `EMAIL_TAKEN`* |
| 413 | `FILE_TOO_LARGE` |
| 415 | `UNSUPPORTED_FILE_TYPE` |
| 422 | `ROUTE_INCOMPATIBLE`, `DEPARTURE_IN_PAST`, `VEHICLE_NOT_ELIGIBLE` |
| 429 | `RATE_LIMITED` |
| 500 | `INTERNAL_ERROR` (no detail, no stack) |

\* Registration never reveals whether an identifier exists (`security.md` §4); `EMAIL_TAKEN` is
only used in authenticated profile updates.

Production responses never contain stack traces or SQL; `requestId` lets support correlate logs.

## 4. Endpoint map

Each row maps to a backend module (`architecture.md` §2.1) and a permission
(`permission-matrix.md`). Phase indicates when it is implemented.

### 4.1 Platform (Phase 1)

| Method & path | Purpose | Auth |
| --- | --- | --- |
| `GET /health/live`, `GET /health/ready` | liveness / readiness (outside `/api/v1`) | none |
| `GET /api/v1/platform/flags` | enabled feature flags relevant to the caller (UI hints only) | optional |
| `GET /api/v1/platform/config` | public runtime config (locales, map tile config, limits shown in UI) | none |

### 4.2 Auth & account (Phase 2) — module `auth`, `users`

| Method & path | Purpose |
| --- | --- |
| `POST /auth/register` | create account (FR-AUTH-01); constant-time response regardless of identifier existence |
| `POST /auth/login` | issue access + refresh (cookie or body per client type) |
| `POST /auth/refresh` | rotate refresh session |
| `POST /auth/logout` | revoke current session |
| `POST /auth/password/forgot`, `POST /auth/password/reset` | reset flow |
| `POST /auth/email/verify`, `POST /auth/email/resend` | identifier verification (⛔ OD-004 may add `/auth/phone/*`) |
| `GET /me`, `PATCH /me` | own account + profile |
| `POST /me/photo` | upload profile photo (public bucket) |
| `GET /me/sessions`, `DELETE /me/sessions/{sessionId}` | session management |
| `DELETE /me` | account deletion — **BLOCKED** ⛔ OD-020 |
| `GET /users/{userId}/public-profile` | badges, display name, photo, rating summary, completed trips, member since |
| `PUT /me/blocks/{userId}`, `DELETE /me/blocks/{userId}`, `GET /me/blocks` | blocking |

### 4.3 Verification (Phase 2 status, Phase 3 documents) — module `verification`, `files`

| Method & path | Purpose |
| --- | --- |
| `GET /me/verification` | identity + driver verification status |
| `POST /me/verification/identity/documents` | multipart upload → private bucket (⛔ OD-002 types) |
| `POST /me/verification/identity/submit` | submit for review |
| `POST /me/verification/driver/submit` | submit driver application (licence + vehicle refs) |

### 4.4 Vehicles (Phase 3) — module `vehicles`

`GET /me/vehicles`, `POST /me/vehicles`, `GET /me/vehicles/{id}`, `PATCH /me/vehicles/{id}`,
`POST /me/vehicles/{id}/deactivate`, `POST /me/vehicles/{id}/documents` (⛔ OD-024 types).

### 4.5 Trips (Phase 4) — module `trips`, `maps`, `pricing`

| Method & path | Purpose |
| --- | --- |
| `GET /maps/autocomplete?q=`, `GET /maps/geocode`, `POST /maps/route-preview` | provider-abstracted map helpers (⛔ OD-005) |
| `POST /trips` | create `DRAFT` (stops, departure, seats, vehicle, notes); server computes route + price |
| `GET /trips/{tripId}` | detail; privacy-filtered by relationship (BR-TRIP-10) |
| `PATCH /trips/{tripId}` | edit (rules BR-TRIP-07, ⛔ OD-023); `If-Match: <version>` |
| `POST /trips/{tripId}/publish` / `/start` / `/complete` / `/cancel` | transitions (§3 state machine) |
| `GET /me/trips?role=driver&status=` | driver's trips (cursor) |
| `GET /me/trips?role=passenger&status=` | passenger's trips via accepted requests (cursor) |
| `GET /pricing/estimate?distanceM=` | server-side price estimate from the active rule |

### 4.6 Search (Phase 5) — module `search`

`GET /search/trips?pickupLat&pickupLng&dropoffLat&dropoffLng&date&timeFrom&timeTo&seats&verifiedOnly&minRating&vehicleType&priceMax&cursor`
→ items with `matchKind: EXACT | ON_ROUTE`, `pickupDistanceM`, `dropoffDistanceM`, blurred
points, driver card. Ordering per BR-MATCH-06. Auth per ⛔ OD-029.

### 4.7 Join requests (Phase 6) — module `bookings`

| Method & path | Purpose |
| --- | --- |
| `POST /trips/{tripId}/join-requests` | create (Idempotency-Key required) |
| `GET /trips/{tripId}/join-requests` | driver: list for trip |
| `GET /me/join-requests` | passenger: my requests |
| `GET /join-requests/{id}` | detail (party only) |
| `POST /join-requests/{id}/accept` / `/reject` / `/cancel` | transitions; accept/cancel run the seat transaction (BR-JOIN-06/07) |

### 4.8 Chat (Phase 7) — module `chat`

`GET /me/conversations`, `GET /conversations/{id}`, `GET /conversations/{id}/messages?cursor`,
`POST /conversations/{id}/messages` (`clientMessageId` for de-dup), `POST /conversations/{id}/read`
(`lastReadMessageId`). WebSocket `/ws` events: `message.created`, `conversation.read`,
`trip.updated`, `trip.seats_changed`, `notification.created`.

### 4.9 Notifications (Phase 7) — module `notifications`

`GET /me/notifications?cursor`, `POST /me/notifications/read` (ids or all), `GET /me/notifications/unread-count`,
`GET /me/notification-preferences`, `PUT /me/notification-preferences`.

### 4.10 Safety & trust (Phase 8) — module `ratings`, `safety`

`POST /trips/{tripId}/ratings`, `GET /users/{userId}/ratings/summary`,
`POST /reports` (Idempotency-Key), `GET /me/reports`.

### 4.11 Admin (Phase 9) — module `admin` (page pagination)

| Path prefix | Operations |
| --- | --- |
| `/admin/users` | search/filter, detail, `POST …/suspend`, `/restore`, `/deactivate`, `PUT …/roles` |
| `/admin/verifications` | queue (identity + driver), detail, `GET …/documents/{fileId}/download-url` (🔒 audited), `POST …/approve`, `/reject` |
| `/admin/vehicles` | list, detail, `POST …/approve`, `/reject` |
| `/admin/trips` | search, detail, `POST …/cancel` (reason) |
| `/admin/reports` | queue, detail, `POST …/status`, `POST …/actions` |
| `/admin/analytics/overview`, `/admin/analytics/timeseries?metric=&from=&to=` | metrics |
| `/admin/settings`, `/admin/feature-flags` | runtime configuration |
| `/admin/audit-logs` | read-only, filter by actor/action/target/date |

### 4.12 AI (Phase 10) — module `ai`

`POST /ai/assistant` `{ "message": "…", "conversationId?": "…" }` → `{ "answer": "…",
"searchParams?": {…validated…}, "tripIds": [...], "interactionId": "…" }`. Flag-gated, rate-limited.

## 5. Versioning & change management (MEP §85)

When an endpoint changes: update backend → regenerate OpenAPI (`scripts/openapi-export`) →
regenerate `packages/types` → fix web types → update tests → note in `docs/api-changelog.md`
(created in Phase 1). CI fails if the committed OpenAPI document differs from the generated one.

## 6. OpenAPI hygiene

- Every route has `summary`, `operationId` (`<module>_<action>`), tags per module, examples.
- Internal/admin routes are included in the schema but marked with `x-internal: true` for the
  public docs build.
- Error responses are declared per route with the `Problem` schema.
- `/api/v1/openapi.json` and Swagger UI are available in `development`/`staging`; disabled in
  production unless behind admin auth.
